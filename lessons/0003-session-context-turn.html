Session, context, turn

The model is stateless. What looks like memory is the session filling a finite box, one turn at a time.

Watch first

Watch Most devs don’t understand how context windows work (~9 min). Then read Session, Turn, and Context window. Cards compress those. They do not replace them.

The video is the box. The dictionary is the names for what fills it.

If the context window is the box, the session is the stuff slowly filling it up.

Session

One user message plus everything the agent does in response, up until it yields back to the user.

Turn

The box is finite

Every model provider request re-sends a single sequence of tokens: system prompt, the conversation so far, every tool result. That sequence is the context window. If it is not in that sequence, grok-4.6 does not know it exists.

Not memory

The window is working state for this request. It does not persist across sessions. Memory is a separate layer that writes to disk and reloads later.

Matt’s punchline in the video: bigger advertised windows still lose the middle. Quality drops before the harness errors. Plan the task for a usable window, not the marketing number.

Session > turn > request

A session is one bounded run with an agent. It starts empty, accumulates messages and tool results, and ends when you close it, clear it, or compact it into a fresh session.

A turn is one of your messages plus everything Jorge does until he yields. One turn can contain many provider requests — each tool call is another round-trip that re-sends the whole prefix.

This Desktop /teach thread is one session. “Ready” later is one turn. Each read_file I run inside that turn is one request.

The cargo-cult

Treating yesterday’s chat as if Jorge still has it. The model is stateless. What survives a new session is the filesystem — GLOSSARY.md, the lesson files, AGENTS.md — not the transcript in his head.

Unrelated work in the same session is residue. It colours the next answer. One task per session is the default; a factory later is a machine that starts those sessions, not a longer one.

Why this lab cares

Work too large for one window must be split across sessions. That is why tickets exist. That is why this teaching thread is HITL and the factory, when we build it, fires new sessions instead of stuffing more into this one.
